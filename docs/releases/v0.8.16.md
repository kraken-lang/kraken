# Kraken v0.8.16 Release Notes

**Release Date**: January 21, 2026

## Overview

Kraken 0.8.16 delivers **Advanced Patterns & Exhaustiveness**: A comprehensive implementation of or patterns, guard clauses, and exhaustiveness checking for match expressions. This release significantly enhances pattern matching capabilities with powerful new syntax and compile-time safety guarantees.

## Or Patterns

### Core Features

- **Or Pattern Syntax**: `1 | 2 | 3 -> { ... }`
- **Multiple Alternatives**: Match against multiple patterns in a single arm
- **AST Representation**: `Pattern::Or { patterns }`
- **Type Checking**: Validates all alternatives are compatible with expression type
- **LLVM Codegen**: Efficient OR chain generation for optimal performance
- **Nested Support**: Or patterns work with guards and other pattern types

### Examples

```kraken
// Basic or pattern
match (x) {
    1 | 2 | 3 -> {
        puts("Small number");
    }
    4 | 5 | 6 -> {
        puts("Medium number");
    }
    _ -> {
        puts("Other");
    }
}

// Or pattern with many alternatives
match (day) {
    1 | 2 | 3 | 4 | 5 -> {
        puts("Weekday");
    }
    6 | 7 -> {
        puts("Weekend");
    }
    _ -> {
        puts("Invalid day");
    }
}

// Or pattern with zero
match (status) {
    0 | 1 | 2 -> {
        puts("Valid status code");
    }
    _ -> {
        puts("Invalid status");
    }
}
```

## Guard Clauses

### Core Features

- **Guard Syntax**: `pattern if condition -> { ... }`
- **Conditional Matching**: Add boolean conditions to patterns
- **AST**: `guard: Option<Expression>` in `MatchArm`
- **Type Checking**: Validates guard expression is bool type
- **LLVM Codegen**: Efficient conditional branching (guard success/fail blocks)
- **Fallthrough**: Failed guards continue to next match arm

### Examples

```kraken
// Basic guard clause
match (x) {
    _ if x > 10 -> {
        puts("Greater than 10");
    }
    _ if x > 5 -> {
        puts("Greater than 5");
    }
    _ -> {
        puts("5 or less");
    }
}

// Guard with complex condition
match (val) {
    _ if val % 2 == 0 -> {
        puts("Even number");
    }
    _ -> {
        puts("Odd number");
    }
}

// Guard with equality
match (target) {
    _ if target == 42 -> {
        puts("The answer!");
    }
    _ -> {
        puts("Not the answer");
    }
}

// Multiple guards
match (score) {
    _ if score >= 90 -> {
        puts("Grade: A");
    }
    _ if score >= 80 -> {
        puts("Grade: B");
    }
    _ if score >= 70 -> {
        puts("Grade: C");
    }
    _ -> {
        puts("Grade: F");
    }
}
```

## Exhaustiveness Checking

### Core Features

- **Compile-Time Safety**: Ensures all possible values are handled
- **Wildcard Detection**: Recognizes `_` and identifier patterns as exhaustive
- **Enum Variant Coverage**: Validates all enum variants are matched
- **Clear Error Messages**: Helpful diagnostics for non-exhaustive matches
- **Or Pattern Support**: Correctly analyzes or patterns for coverage

### Exhaustiveness Rules

1. **Wildcard Pattern (`_`)**: Always exhaustive
2. **Identifier Pattern (`x`)**: Always exhaustive (binds any value)
3. **Enum Variants**: Exhaustive if all variants are covered
4. **Or Patterns**: Exhaustive if any alternative is exhaustive
5. **Primitive Types**: Require wildcard for exhaustiveness

### Examples

```kraken
// Exhaustive with wildcard
match (x) {
    1 -> { puts("One"); }
    2 -> { puts("Two"); }
    _ -> { puts("Other"); }  // Wildcard makes it exhaustive
}

// Exhaustive with identifier
match (x) {
    n -> { puts("Any value"); }  // Identifier is exhaustive
}

// Non-exhaustive (compile error)
match (x) {
    1 -> { puts("One"); }
    2 -> { puts("Two"); }
    // ERROR: Non-exhaustive match expression for type int.
    // Add a wildcard pattern (_) to handle all cases.
}

// Exhaustive enum matching
match (option) {
    Option::Some(x) -> { puts("Has value"); }
    Option::None -> { puts("No value"); }
    // All variants covered - exhaustive!
}

// Or pattern with wildcard
match (x) {
    1 | 2 | _ -> { puts("Matches everything"); }
    // Exhaustive because or pattern contains wildcard
}
```

## Implementation Details

### Or Pattern Codegen

Or patterns generate efficient OR chains in LLVM:

```kraken
// Source
match (x) {
    1 | 2 | 3 -> { body }
}

// Generated LLVM (conceptually)
if (x == 1 || x == 2 || x == 3) {
    body;
}
```

### Guard Clause Codegen

Guard clauses create conditional branches:

```kraken
// Source
match (x) {
    _ if x > 10 -> { body }
}

// Generated LLVM (conceptually)
if (x > 10) {
    body;  // Guard success
} else {
    // Guard fail - continue to next arm
}
```

### Exhaustiveness Algorithm

The exhaustiveness checker uses a multi-phase approach:

1. **Wildcard Detection**: Check for `_` or identifier patterns
2. **Enum Analysis**: For enum types, verify all variants are covered
3. **Or Pattern Analysis**: Recursively check or pattern alternatives
4. **Error Reporting**: Provide clear, actionable error messages

## Performance

- Or patterns compile to efficient OR chains (no overhead)
- Guard clauses use direct conditional branching
- Exhaustiveness checking is compile-time only (zero runtime cost)
- Pattern matching remains zero-cost abstraction
