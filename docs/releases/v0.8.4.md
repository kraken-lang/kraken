# Kraken Language v0.8.4

**Release:** v0.8.4
**Published:** 2025-12-15

## Summary
v0.8.4 begins Standard Types v1 by introducing `bytes` as a distinct primitive for raw buffers/opaque pointers and tightening the libc/FFI boundary. It also adds v1 byte indexing for `bytes` and `string` plus explicit C-string interop helpers.

## Highlights
- **`bytes` primitive**: a dedicated type for raw pointers/buffers distinct from `string`.
- **FFI boundary tightening**: libc buffer/handle APIs now take/return `bytes` instead of `string`.
- **Interop helpers**: `cstr(string) -> bytes` and `from_cstr(bytes) -> string` for explicit C-string boundary control (`from_cstr` traps on null).
- **Indexing**: v1 byte indexing for `bytes[i]` and `string[i]`.

## Breaking changes (if any)
- **Stdlib/FFI signature tightening**: raw buffers and opaque handles were migrated from `string` to `bytes`.
  - **Migration**: update program annotations and intermediate variables passed to `malloc/free/realloc/mem*` and `FILE*`-style APIs to use `bytes`.

## Changelog
### Added
- Added a new primitive type `bytes` for raw pointer/buffer values (separate from `string`).
- Added v1 byte indexing support for `bytes[i]` and `string[i]` (returns `int`).
- Added FFI C-string boundary helpers `cstr(string) -> bytes` and `from_cstr(bytes) -> string` (traps on null).

### Changed
- Stdlib/FFI signatures now use `bytes` for raw buffers and opaque pointer handles (e.g. `malloc/free/realloc`, `mem*`, and `FILE*`-like values), while `string` remains for C-string text.
