# Kraken v0.8.14 Release Notes

**Release Date**: January 21, 2026

## Overview

Kraken 0.8.14 delivers **Tuples, Enums & Pattern Matching**: A comprehensive type system foundation featuring tuple types with destructuring, enum variants with payloads, and powerful pattern matching. This release establishes the core building blocks for advanced type-safe programming patterns.

## Tuple Types

### Core Features

- **Tuple Type Syntax**: `(int, string, bool)`
- **Tuple Literals**: `(1, "hello", true)`
- **Tuple Indexing**: `tuple.0`, `tuple.1`, `tuple.2`
- **Empty Tuple**: `()` as unit type
- **Nested Tuples**: Full support for arbitrary nesting
- **LLVM Codegen**: Efficient struct-based representation with `extractvalue` instructions

### Tuple Destructuring

- **Let Destructuring**: `let (x, y, z) = tuple;`
- **Wildcard Patterns**: `let (a, _, c) = tuple;`
- **Nested Destructuring**: `let ((x, y), z) = nested;`

### Tuple Pattern Matching

- **Match Expressions**: `match (tuple) { (x, y) -> { ... } }`
- **Mixed Patterns**: `(a, _, c) -> { ... }`
- **Nested Patterns**: `((x, y), z) -> { ... }`
- **Proper Scope Management**: Pattern variables correctly bound in match arm bodies

## Enum Type System

### Features

- **Enum Variants with Tuple Payloads**: `Some(T)`, `Err(E)`
- **Pattern Matching**: Full support for enum variant patterns
- **Memory Layout**: Tagged unions with discriminant + max variant size
- **LLVM Codegen**: Efficient enum construction and access

### Standard Library Enums

- **Option Enum**: `Option::Some(value)`, `Option::None`
  - Helper functions: `option_is_some`, `option_is_none`, `option_unwrap`, `option_unwrap_or`
- **Result Enum**: `Result::Ok(value)`, `Result::Err(error)`
  - Helper functions: `result_is_ok`, `result_is_err`, `result_unwrap`, `result_unwrap_or`, `result_expect`

## Pattern Matching

### Supported Patterns

- **Literal Patterns**: `1`, `"hello"`, `true`
- **Wildcard Pattern**: `_`
- **Binding Patterns**: `x`, `name`
- **Tuple Patterns**: `(x, y)`, `(1, _)`
- **Enum Variant Patterns**: `Some(x)`, `Ok(value)`
- **LLVM Codegen**: Efficient switch tables for match expressions

## Compiler Infrastructure

### AST Enhancements

- `Type::Tuple { element_types }`
- `Expression::Tuple { elements }`
- `Expression::TupleIndex { tuple, index }`
- `Pattern::Tuple { patterns }`

### Type Checker

- Full tuple type validation
- Pattern binding with proper scope management
- Tuple destructuring type checking

### Monomorphization

- Tuple type support in generic instantiation
- Pattern rewriting with type substitutions

### IR & Codegen

- `IrType::Tuple` representation
- Tuple lowering to IR
- LLVM struct-based tuple implementation
- `extractvalue` instruction for tuple element access

## Known Limitations

- Single-element tuple syntax not supported (requires trailing comma)
- Chained tuple indexing not supported (e.g., `tuple.0.0`)
- Option/Result not generic yet (hardcoded to `int`)
- Nested generic types not supported yet
