# Kraken v0.8.6 Release Notes

**Release Date**: December 17, 2025

## Overview

Kraken 0.8.6 introduces the **Compiler IR Boundary** - a new intermediate representation (IR) layer between the AST and LLVM codegen. This architectural change enables future transformations like async state machine lowering, optimizations, and alternative backends.

## New Features

### Compiler IR Stage

The compiler now uses a three-stage architecture:

```
Source → AST → Kraken IR → LLVM IR → Binary
```

**Benefits:**
- Clean separation between frontend (parsing/type-checking) and backend (code generation)
- Enables complex transformations (async, optimizations) at the IR level
- Backend-agnostic design allows future alternative backends
- Easier debugging with IR dump capability

### IR Dump (`--emit-ir`)

New compiler flag to inspect the intermediate representation:

```bash
kraken build --emit-ir examples/hello.kr
```

Outputs human-readable IR for debugging and development.

## Architecture

### IR Data Structures

| Type | Description |
|------|-------------|
| `IrProgram` | Top-level program container |
| `IrFunction` | Function with blocks |
| `IrBlock` | Basic block with instructions |
| `IrInstruction` | Individual operation |
| `IrValue` | Values (constants, registers) |
| `IrType` | Type information |

### Compilation Pipeline

1. **Lexer** → Tokens
2. **Parser** → AST
3. **Type Checker** → Typed AST
4. **IR Lowering** → Kraken IR *(new)*
5. **LLVM Codegen** → LLVM IR
6. **LLVM/Clang** → Binary

## Implementation Notes

### v1 Limitations

- IR is structurally similar to AST (minimal transformation)
- No optimization passes yet
- Desugar passes (`for` → `while`, `defer`) deferred to 0.8.7

### Files Added

- `compiler/src/ir/mod.rs` - IR module entry point
- `compiler/src/ir/types.rs` - IR type definitions
- `compiler/src/ir/lower.rs` - AST → IR lowering

## Upgrade Guide

No breaking changes from 0.8.5. The IR layer is internal to the compiler.
