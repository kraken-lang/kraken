# Kraken Language v0.8.3

**Release:** v0.8.3
**Published:** 2025-12-15

## Summary
Modules + imports (ecosystem unlock): file-based module resolution, namespace rules, and diagnostics.

## Highlights
- File-based `import foo.bar;` module loading (relative-first, then entry-directory root).
- Enforced `module foo.bar;` declarations (single per file, must be first statement, must match file path).
- Module visibility: `pub` exports remain visible; non-`pub` top-level symbols are module-private via stable mangling.
- Hardened diagnostics and negative tests: unresolved imports, import cycles, duplicate symbols, module decl mismatch.

## Breaking changes (if any)
- Module-only source files without `main` are now treated as libraries: `kraken build <dir>` skips them.
- `kraken run` now propagates the program's exit code (including non-zero) instead of treating non-zero as an error.

## Changelog
### Added
- File-based module loader with recursive import expansion.
- `module` declarations in lexer/parser/AST.
- Multi-file modules example under `examples/`.
- New regression tests for module loader behavior and diagnostics.

### Changed
- Type checker now predeclares top-level functions/types before checking bodies (order-independent modules).
- Imports require imported files to declare a matching `module` path.

### Fixed
- Duplicate symbol detection for top-level functions/types.
- Preserved `main` entrypoint from symbol mangling so executables continue to link.
- Stable module-private symbol mangling by hashing file paths relative to the program root.
- CLI: directory builds skip files without `main`; `run` propagates exit status.
